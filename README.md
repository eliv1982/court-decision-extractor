# Извлечение данных из судебных решений

Python-инструмент для извлечения структурированных данных из судебных решений (скан-образы, PDF) с использованием мультимодальной модели OpenAI GPT-4o. **Анализирует весь документ** (все страницы PDF или одно изображение), объединяет результаты полей по страницам и выдаёт один JSON: выбранное резюме страницы, ключевые выводы и структурированные поля без выгрузки полного текста.

## Возможности

- **Входные форматы:** изображения (`.jpg`, `.jpeg`, `.png`) и PDF
- **Анализ всего документа:** для PDF по умолчанию обрабатываются **все страницы**; каждая страница анализируется отдельно, результаты объединяются в один итоговый JSON (тип документа, суд, номер дела, стороны, резолютивная часть, правовые основания, ключевые выводы и т.д.). Поле `summary` — это **самое длинное непустое резюме среди страниц**, а не заново синтезированное резюме всего документа
- **Режим одной страницы:** флаг `--first-page-only` — обрабатывается только первая страница PDF (для экономии токенов)
- **Выход:** единый JSON с полями: тип документа, суд, номер дела, дата, судья, стороны, сумма иска, резолютивная часть, правовые основания, резюме, ключевые выводы, персоны, даты, суммы, таблицы
- **Structured Outputs:** ответ модели запрашивается по строгой JSON Schema (`response_format` / `json_schema`, `strict: true`) через Chat Completions

### 2. Poppler (для работы с PDF)

Инструмент использует `pdf2image`, которому нужен **Poppler**. Без него при обработке PDF появится ошибка: *"Unable to get page count. Is poppler installed and in PATH?"*

#### Вариант А: Poppler в PATH (пошагово для Windows)

**Шаг 1. Скачать Poppler**

1. Откройте: https://github.com/oschwartz10612/poppler-windows/releases
2. В **Assets** скачайте архив, например `Release-24.08.0-0.zip` (или более новый).

**Шаг 2. Распаковать**

1. Извлеките архив, например в `C:\Program Files\poppler`.
2. Найдите папку **`bin`** внутри (часто `...\Release-...\Library\bin`).
3. Запомните полный путь к **`bin`**, например:
   `C:\Program Files\poppler\Release-24.08.0-0\Library\bin`

**Шаг 3. Добавить `bin` в PATH**

1. **Win + R** → `sysdm.cpl` → Enter.
2. **Дополнительно** → **Переменные среды**.
3. В переменных пользователя выберите **`Path`** → **Изменить** → **Создать**.
4. Вставьте путь к папке **`bin`** → **ОК** во всех окнах.
5. Закройте и заново откройте терминал (и IDE), чтобы PATH обновился.

**Шаг 4. Проверить**

```powershell
pdfinfo -v
```

Если команда не найдена, проверьте `bin` напрямую:

```powershell
& "C:\path\to\poppler\Library\bin\pdfinfo.exe" -v
```

Либо используйте Вариант Б с `POPPLER_PATH`.

---

**Вариант Б (без PATH):** укажите в `.env` путь к папке `bin`:

```env
POPPLER_PATH=C:\path\to\poppler\Library\bin
```

**macOS:** `brew install poppler`  

**Linux (Debian/Ubuntu):** `sudo apt install poppler-utils`

## Использование

```bash
python main.py <path_to_file> [--output OUTPUT] [--model MODEL] [--first-page-only] [--pretty]
```

| Аргумент | Описание |
|----------|----------|
| `path_to_file` | Обязательный. Путь к PDF или изображению |
| `--output`, `-o` | Файл для сохранения JSON (по умолчанию вывод в stdout) |
| `--model` | Модель OpenAI (по умолчанию: `gpt-4o`) |
| `--first-page-only` | Обрабатывать только первую страницу PDF (для экономии токенов) |
| `--pretty` | Форматировать JSON с отступами |

### Как обрабатывается многостраничный PDF

1. PDF конвертируется в изображения (по одной на страницу) через `pdf2image`.
2. Каждая страница отправляется в GPT-4o; модель возвращает частичный JSON по этой странице (Structured Outputs / JSON Schema).
3. Функция `merge_results` объединяет частичные результаты:
   - обычные уникальные поля (суд, номер дела, стороны и т.д.) — **первое непустое** значение;
   - `ruling` — **последнее непустое** значение (резолютивная часть чаще ближе к концу документа);
   - списки (персоны, даты, суммы, таблицы, ключевые выводы, правовые основания) — конкатенация;
   - `summary` — **самое длинное** непустое резюме среди страниц (не синтез всего документа).
4. Постобработка `postprocess`: дедупликация `people` и `legal_basis`, нормализация чисел и дат, приведение `key_findings` к `{finding, evidence}`. Постобработка **не** дописывает кодекс в `legal_basis` и **не** подменяет неизвестную роль на «представитель».

В результате вы получаете **один JSON на весь документ** (с оговоркой по семантике `summary` выше).

### Примеры

```bash
# Весь документ (все страницы PDF), результат в консоль
python main.py решение.pdf

# Путь с пробелами (Windows) — в кавычках
python main.py "C:\path\to\Мои документы\решение.pdf"

# Результат в файл, красивый JSON
python main.py "C:\path\to\decision.pdf" -o result.json --pretty

# Только первая страница PDF (экономия токенов)
python main.py решение.pdf --first-page-only

# Один скан/фото страницы
python main.py scan_1.jpg -o out.json --pretty
```

## Структура ответа (JSON)

- `document_type`, `court_name`, `case_number`, `date`, `judge`, `plaintiff`, `defendant`, `third_party`
- `date` и `dates[].value`: при успешной нормализации — **`YYYY-MM-DD`**; непарсабельные даты не выдумываются
- `claim_amount`: `{ "value": число, "currency": "руб." }`
- `claim_subject`, `ruling`
- `legal_basis`: массив строк (`ст. N …`); кодекс только если он был в извлечении — голая «ст. N» остаётся без дописанного кодекса
- `summary` — краткое резюме (всегда присутствует): для многостраничного PDF — выбранное резюме страницы (самое длинное непустое)
- `key_findings`: массив `[{ "finding": "текст вывода", "evidence": "цитата из решения" }]` (всегда присутствует)
- `people`: `[{ "full_name": "ФИО в И.п.", "role": "..." }]` (дедупликация по ФИО+роль; неизвестная роль сохраняется)
- `dates`: `[{ "label": "...", "value": "YYYY-MM-DD" }]`
- `amounts`: `[{ "label": "...", "value": число, "currency": "..." }]`
- `tables`: `[{ "name": "...", "columns": [], "rows": [] }]`

Поля, которые не удалось извлечь, могут быть `null` или отсутствовать после объединения; `summary` и `key_findings` возвращаются всегда.

## Обработка ошибок

- **Файл не найден** — проверьте путь к файлу
- **Нет OPENAI_API_KEY** — задайте ключ в `.env` или в переменной окружения
- **Ошибка OpenAI API / сети / авторизации** — сообщение об ошибке API без вывода ключа
- **Отказ модели (refusal)** — запрос не обработан по решению модели
- **Ошибка конвертации PDF** — установите Poppler и добавьте его в `PATH` или задайте `POPPLER_PATH`
- **Неподдерживаемый формат** — используйте `.jpg`, `.jpeg`, `.png` или `.pdf`
- **Windows: путь не распознаётся** — заключите путь с пробелами в кавычки

## Ограничения

- Модель может ошибаться по фактам даже при валидной JSON-структуре.
- Structured Outputs проверяет **форму** ответа, а не юридическую/фактическую корректность.
- Детерминированная постобработка — это нормализация и дедупликация, а не юридическая проверка.
- Постраничная обработка больших PDF может быть медленной и затратной по токенам; используйте `--first-page-only`, если достаточно первой страницы.
- Итоговое `summary` выбирается из резюме страниц (сейчас — самое длинное непустое), а не синтезируется заново по всему документу.

## Конфиденциальность и обработка данных

- Ключ API загружается из `OPENAI_API_KEY` (в том числе через файл `.env` и `python-dotenv`). Не публикуйте `.env` и не добавляйте его в репозиторий.
- Это **не** локальный/офлайн OCR: при обработке документа **изображения страниц (содержимое документа) передаются в OpenAI API**.
- Перед обработкой судебных материалов оцените требования к конфиденциальности и персональным данным.
- Политика хранения и использования данных API со стороны OpenAI описана в их документации; не полагайтесь на устаревшие или неподтверждённые утверждения о сроках хранения. См. [OpenAI API data controls / privacy](https://platform.openai.com/docs/guides/your-data).
